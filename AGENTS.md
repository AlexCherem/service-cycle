# Service Cycle: контекст проекта

## Продукт

- Service Cycle — B2B-сервис для простой загрузки клиентской базы и возврата клиентов на плановое обслуживание оборудования.
- Это не копия Bitrix24 и не универсальная CRM. Главная ценность: напоминание о сервисе, фиксация отклика, задача сотруднику и измеримый возврат выручки.
- Первый релиз должен быть небольшим и ориентированным на один VPS.

## Команда и способ работы

- Проект разрабатывают два человека: пользователь пишет backend и ревьюит frontend; второй разработчик — junior frontend-разработчик.
- Пользователь впервые пишет backend, поэтому изменения нужно делать небольшими шагами.
- Перед добавлением нового слоя или важного файла объяснять его назначение и место в общей цепочке.
- Не создавать много заготовок и пустых файлов заранее. Добавлять структуру вместе с первой реальной функцией.
- Основная совместная работа с Codex: разработка backend и ревью frontend.

## Зафиксированный стек

- Monorepo: pnpm workspaces.
- `apps/web`: Next.js 16, App Router, React 19, TypeScript, Ant Design 6, Turbopack.
- `apps/api`: NestJS 11, TypeScript.
- PostgreSQL, Prisma, Docker Compose.
- Swagger/OpenAPI для документации и контракта API.
- Node.js 22+, pnpm 11+.
- Первоначальное развёртывание: один VPS.

## Команды workspace

- Весь проект: `pnpm dev`.
- Только frontend: `pnpm dev:web` или `pnpm --filter web dev`.
- Только backend: `pnpm dev:api` или `pnpm --filter api dev`.
- Новые зависимости ставить в конкретный пакет через `pnpm --filter web add ...` или `pnpm --filter api add ...`.

## Архитектура frontend

- Использовать облегчённый FSD-подход, адаптированный под Next.js App Router.
- Направление зависимостей: `app -> views -> widgets -> features -> entities -> shared`.
- `app` отвечает за маршруты, layouts и глобальные providers.
- `views` заменяет FSD-слой `pages` и отвечает только за композицию целого экрана.
- `widgets` содержит крупные самостоятельные блоки интерфейса.
- `features` содержит действия пользователя, `entities` — бизнес-сущности, `shared` — общий технический код.
- `page.tsx` должен быть тонким и импортировать конкретный view напрямую, например `@/views/clients`, без общего barrel-файла всех views.
- Использовать route groups `(auth)`, `(workspace)` и `(public)` по мере появления соответствующих маршрутов.
- Не ставить `"use client"` на целый view без необходимости; держать клиентскую границу ближе к интерактивному компоненту.

## Ant Design

- `antd` и `@ant-design/icons` уже установлены в `apps/web`.
- Для App Router при первой UI-задаче подключить `@ant-design/nextjs-registry` через один корневой `AntdRegistry`.
- Общие React/Ant providers держать в `app/providers`, а типизированную тему — в `shared/config/antd`.
- Начать с небольшого набора глобальных token-ов из дизайна; component token-ы добавлять только при реальной необходимости.
- Не использовать `@ant-design/v5-patch-for-react-19`: проект работает на Ant Design 6.
- Для первых форм использовать правила `Form` из Ant Design. Yup не установлен; Zod оценить при появлении первой сложной формы или общего контракта.

## Архитектура backend

- Модульный монолит NestJS, без микросервисов.
- Основная цепочка: `Controller -> Service -> Prisma -> PostgreSQL`.
- Разделять код по бизнес-модулям: companies, users, clients, equipment, imports, service-cycles, notifications, responses.
- Не добавлять отдельный Repository-слой на старте без реальной необходимости.
- Данные арендаторов изолировать через `companyId`.

## Контракты API

- Назначение `packages/contracts` окончательно не выбрано.
- Предпочтительное направление: NestJS DTO как источник Swagger/OpenAPI и генерация типизированного frontend-клиента.
- Не создавать общий пакет контрактов до первого реального endpoint и отдельного решения по генерации.

## Ближайшее техническое направление

- Сначала поднять PostgreSQL через Docker Compose, подключить Prisma к NestJS и проверить полный путь `Next.js -> NestJS -> Prisma -> PostgreSQL` на одном небольшом сценарии.
- После инфраструктурной проверки первым продуктовым сценарием должен стать импорт клиентской базы.
